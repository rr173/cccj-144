# 地块边界整理工具（parcel_boundary）

本地地块边界资料接入与清洗：把**已声明相邻关系**中的共享边界校成一份一致的
几何，交付可供数仓使用的地块面、共享边目录和逐地块来源说明。
本工具只做边界清洗，不计算地价、风险或其他空间指标。

## 功能与规则

- 输入为同一平面坐标系的地块多边形（外环 + 可选洞）、地块标识、来源标识、
  来源优先级，以及相邻地块与共享边界标识的清单。
- **只有清单声明相邻的两个地块才会被协调**；不在清单中的近邻边、洞边和
  外边界不因距离接近而被吸附。一个边界标识只允许指向一对不同地块。
- 两侧对同一条法定边界的描述可以方向相反、起点不同、折点数量不同
  （一侧一个长线段可对应另一侧多个短线段）。程序在容差内找到两侧实际
  重合意图的边界部分，整理成同一条有序共享边；相邻两块的环都引用它，
  方向相反（导入时外环统一规范为逆时针、洞为顺时针，仅反转顶点顺序，
  几何不变）。
- 只改共享部分：地块其余边与洞保持不变，地块标识、来源和属性保留。
- 来源优先级较高的一侧提供共享边的基准形状；优先级相同且两侧坐标不一致时，
  按归一化弧长参数逐点取中点合并——结果只取决于几何内容，**不随输入顺序
  挑边**。
- 每个边界组独立判定：配对不唯一、偏移超过容差、清单引用不存在的地块、
  边界不能沿地块环闭合、整理后多边形无效、任一地块面积变化超上限——
  该组不发布为已修复结果，保留原始地块并输出可定位的冲突原因；
  其他彼此无关且合格的边界组照常处理。
- 输入结构错误（JSON 畸形、缺字段、非有限坐标、多边形无效、标识重复等）
  则**整次运行失败**，不生成看似完整的正式输出。

## 命令入口

```bash
# 0. 跨期事实转接（详见 TRANSFER.md，需要 Shapely >= 2.0）
python -m parcel_boundary transfer --chain chain.json --facts facts.jsonl --out OUT
python -m parcel_boundary query --out OUT row F17
python -m parcel_boundary query --out OUT final-parcel X

# 1. 导入：校验并暂存输入（可多个文件，合并校验；结构错误则失败）
python -m parcel_boundary import --store STORE input1.json [input2.json ...]

# 2. 检查冲突：对暂存输入跑完整协调，报告写入 staging/（非正式输出）
python -m parcel_boundary check --store STORE --tolerance 0.05 --max-area-change 0.5

# 3. 发布：全部候选组检查完成后，把结果原子发布为新版本 versions/v<N>
python -m parcel_boundary publish --store STORE --tolerance 0.05 --max-area-change 0.5

# 4. 查询：指定地块（几何+来源说明）或共享边（目录记录/冲突原因）
python -m parcel_boundary query --store STORE parcel P1
python -m parcel_boundary query --store STORE boundary B1 [--version 1]
```

## 容差与面积上限的单位和作用

| 参数 | 单位 | 作用 |
|---|---|---|
| `--tolerance` | **长度单位**，与坐标系一致（坐标为米则为米） | 判定两侧描述是否为同一条边界的最大允许偏差：端点配对、共享链识别、链间偏差都用它。两侧几何间距超过容差则不吸附（如超容差窄缝保留原状并隔离）。 |
| `--max-area-change` | **面积单位**，坐标单位的平方（如平方米） | 单个地块从原始到最终发布几何允许的**最大累计面积变化**（鞋带公式绝对值）。任一地块超限，相关边界组整体不发布，保留原始地块。 |

## 输入格式

每个输入文件是一个 JSON 对象，可含以下键（可多文件合并）：

```json
{
  "crs": "LOCAL",                          // 可选；多文件须一致
  "sources": [{"id": "SA", "priority": 10}],
  "parcels": [{
    "id": "P1", "source": "SA",
    "attributes": {"lot": "A-17"},
    "exterior": [[0, 0], [10, 0], [10, 4], [0, 4]],
    "holes": [[[2, 2], [2, 3], [3, 3], [3, 2]]]
  }],
  "adjacencies": [{"boundary": "B1", "parcels": ["P1", "P2"]}]
}
```

坐标为有限十进制数；输入多边形必须有效（环简单、洞在外环内）。
环可写可不写重复闭合点；外环/洞的走向任意（导入时统一规范化）。

## 正式输出（versions/v<N>/）

- `parcels.json`：全部地块面（含未改动的），可追溯来源标识与属性。
- `shared_boundaries.json`：共享边目录——稳定标识（清单中的边界标识）、
  两侧地块、目录方向（`direction.from/to`，起点为字典序较小端点）、
  坐标、长度、基准形状来源、各地块环相对目录的方向（forward/backward）。
- `conflicts.json`：冲突清单——边界标识、涉及地块、代码、可定位的原因
  与细节（容差、偏差量、面积变化等）。
- `provenance.json`：逐地块来源说明——来源标识、原始/最终面积、面积变化、
  每次改动的边界标识与被替换的顶点范围（旧链/新链坐标）。
- `manifest.json`：容差与面积上限、输入 SHA-256、计数、各产物哈希。

**原子发布**：所有候选组检查完成后才发布；新版本先完整写入临时目录并改名
就位，最后原子切换 `current.json` 指针。旧版本在新结果完整之前保持可读，
历史版本保留在 `versions/` 下可查询。

**确定性**：相同输入重跑、打乱输入文件与记录顺序，被接受的边、冲突分类和
输出坐标完全一致（输入在导入时即规范化排序，处理按边界标识排序进行）。

## 冲突代码

| 代码 | 含义 |
|---|---|
| `UNKNOWN_PARCEL` | 清单引用不存在的地块 |
| `SELF_ADJACENCY` | 相邻对是同一地块（须为一对不同地块） |
| `BOUNDARY_ID_MULTIPLE_PAIRS` | 一个边界标识指向多对地块 |
| `NO_SHARED_GEOMETRY` | 容差内找不到可配对的共享边界（如超容差窄缝） |
| `ENDPOINT_MISMATCH` | 边界不能沿地块环闭合（两侧链端点对不上） |
| `AMBIGUOUS_MATCH` | 配对不唯一（多组链或两种方向都能配对） |
| `DEGENERATE_CHAIN` | 共享链退化（整条环贴合、点接触或零长度） |
| `OFFSET_BEYOND_TOLERANCE` | 链中部偏移超过容差 |
| `AREA_CHANGE_EXCEEDED` | 某地块累计面积变化超过上限 |
| `INVALID_RESULT` | 整理后多边形无效（自相交、洞跑出外环等） |

## 测试

```bash
python3 tests/run_tests.py              # 原有 23 个用例
python3 tests/run_transfer_tests.py    # 跨期事实转接验收
```

23 个手算核对用例：预期坐标由手写折线与鞋带公式独立计算，不用生产修复
函数生成；拓扑检查独立确认共享段逐点反向相等、地块环闭合、各组面积变化
在界内；并对同一数据重跑与乱序重排逐项比较发布物和冲突清单。

## 已知限制

- 跨期事实转接只读正式发布物，不做坐标转换、不重协调共享边；详见 `TRANSFER.md`。
- 共享边界的端点必须是两侧环上的顶点（容差内）；端点落在一侧边的中间
  （T 型接头）时判为 `ENDPOINT_MISMATCH`/`NO_SHARED_GEOMETRY` 冲突而不强行
  整理。洞不参与共享边界整理。
- 不校验不同地块多边形之间是否重叠（输入要求各地块自身有效）。
- 链间偏差用顶点加 1/4 采样近似豪斯多夫距离，对地籍折线足够稳健。
